# 领域包 · 硬件（hardware）

## 槽位 1 · 交付实体

```
05-实现/ 放：原理图（PDF/源文件）、PCB 文件、BOM（含替代料）、固件源码、结构件图纸、
            测试记录（台架原始数据）、装配与调试说明
由谁使用：采购（BOM）、工厂（图纸/工艺）、测试（记录）、售后（调试说明）
怎么确认真实：有可下单的 BOM、有可打样的文件、有实测数据 —— 不是"设计构想"
```

**禁止的假交付**：只有框图没有参数、BOM 缺封装/耐压/精度、测试记录是"预计满足"而非实测、固件是伪代码、图纸无版本号。

**硬件特有的一条**：**没有实测数据的"验证"，一律记为"未验证"**，不得标"通过"。软件可以靠推理近似，硬件不行。

## 槽位 2 · 验证方式

```
判定手段：仿真（电路/热/结构）→ 计算（裕量/公差）→ 样机台架实测 → 第三方认证
执行者：设计者出仿真、测试工程师做台架、第三方做认证
反馈周期：
  仿真/计算：小时级
  PCB 打样：3–5 天（加急 24h），改版一轮 2–3 周
  结构件打样：1–2 周（含模具则 4 周+）
  台架测试：1–3 天/轮
  EMC 预测试：1 周；正式认证：4–6 周
做一次验证的成本：单轮打样+测试约 数千至数万元；认证 数万起
外部机构：EMC 实验室、安规认证机构、可靠性实验室
```

**核心原则（与软件相反）**：硬件的试错成本高一个数量级，所以**验证必须前置到仿真和计算**，而不是"做出来再看"。

> 软件的逻辑是"试错便宜，所以多试"。
> 硬件的逻辑是"试错昂贵，所以先在纸上算清楚"。

这条要写进 `03` 的取舍理由里：任何"先做出来再调"的方案，必须说明为什么不能先仿真。

## 槽位 3 · 方案载体

`03-架构方案.md` 里的"架构"指：

```
1. 系统框图（功能模块 + 信号/功率流向）
2. 电源树（输入→各级转换→负载，每级效率与裕量）
3. 接口定义（电平标准、速率、时序、连接器型号与针序）
4. BOM 关键项（主控/电源/功率器件/连接器，含生命周期状态）
5. 热路径（热源→导热→散热→环境，热阻链与结温计算）
6. 结构与装配（干涉检查、装配顺序、紧固方式）
7. 公差链（关键尺寸的累积公差与最坏情况）
```

**必须量化的**（不给数字就不算写完）：

| 项 | 必须给 |
|---|---|
| 结温 | 最高环境温度下的 Tj 与裕量（建议 ≥15°C） |
| 电源 | 每级输出在最坏负载下的压降与纹波 |
| 公差 | 关键配合的最坏情况累积值 vs 允许值 |
| 寿命 | 关键器件（电解电容/风扇/继电器）的寿命估算 |
| 降额 | 电阻功率/电容耐压/器件电流的降额比例 |

## 槽位 4 · 攻击面

reviewer 优先攻击这七类：

| # | 攻击面 | 具体打点 |
|---|---|---|
| 1 | **公差累积** | 单件合格但装配后干涉；最坏情况未算；未考虑来料公差带 |
| 2 | **热** | 最高环温下结温超限；热点未识别；散热路径被结构件挡住；无风/堵风场景 |
| 3 | **EMC / EMI** | 开关电源环路面积、地平面分割、时钟走线跨分割、线缆天线效应、ESD 路径 |
| 4 | **电源裕量** | 上电时序（谁先谁后）、浪涌电流、掉电保持、纹波在满载+低温下恶化 |
| 5 | **器件生命周期** | 主控/电源 IC 是否 NRND/停产；交期是否 >12 周；替代料参数是否等价 |
| 6 | **环境与可靠性** | 温循、湿热、振动、跌落、盐雾；连接器插拔寿命；三防漆是否影响散热 |
| 7 | **可制造 / 可测试（DFM/DFT）** | 最小线宽线距、焊盘与钢网、测试点是否可达、是否需要工装、返修是否可行 |

附加：安规间距（爬电/电气间隙）、电池（过充过放/热失控）、固件的失效安全（看门狗/默认态）。

## 槽位 5 · 角色映射

| 通用角色 | 本领域角色 | 职责偏移 | 额外要求 |
|---|---|---|---|
| lead | 项目负责人 | 要管采购与打样排期 | 懂关键器件交期 |
| spec | 需求分析师 | 要出"环境与合规约束"（温度/防护等级/认证） | 明确使用场景的最坏条件 |
| architect | 系统架构师 | 见槽位 3 的七项 | 必须给仿真/计算结论，不是判断 |
| builder | 硬件工程师 | 出图 + BOM + 固件 + 调试 | 每个关键设计有计算书 |
| reviewer | 设计评审员 | 见槽位 4 | **必须有同类产品经验**；能看懂计算书 |
| （可加） | EMC/安规评审 | 专项评审 | 挂在 G2 之后 |

**reviewer 的独立性在硬件里尤其重要**：硬件的问题往往"看起来能工作"，只有做过同类产品的人才知道哪里会炸。

## 槽位 6 · 附加合规

```
必须过的关卡：
  EMC（辐射/传导/抗扰）—— CE / FCC / 3C，按销售地
  安规（IEC 62368-1 等）—— 爬电距离、绝缘耐压、温升
  环保（RoHS / REACH）
  可靠性（按行业：消费类跌落、车载 AEC-Q100、医疗 IEC 60601）
  无线（若含射频）—— SRRC / CE-RED
谁签：第三方认证机构 + 企业安规负责人
挂在哪个门禁上：G2（选型与结构定案时预判能否过）与 G3（有正式报告才交付）
```

**注意**：认证不在 G3 才想。选型阶段就要判断"这个方案能不能过 EMC"，否则打样两次才发现过不了，代价是数周与数万元。

## 槽位 7 · 判定用语

```
合格：25°C 与 60°C 环境下，主控结温实测分别为 62°C / 88°C，均低于 Tj(max)=105°C 且裕量 ≥15°C
合格：按 IEC 61000-4-2 接触放电 ±8kV，10 次无复位、无死机、无数据丢失
不合格：散热良好，温度在可接受范围
不合格：EMC 表现良好，符合行业惯例
本领域禁用语：稳定可靠、余量充足、满足工业级、经过优化
```

## 槽位 8 · 判级门槛

```
S：换一个阻容、改一句固件参数、不改板
M：改一个功能模块（含小改板一次）、新增一个接口
L：新板 / 新结构 / 新认证 / 新供应链（含模具、认证、长交期料）
典型陷阱：改一颗料看起来是 S，但新料封装不同 → 要改板 → 实际是 L
         加一个功能看起来是 M，但触发了新认证 → 实际是 L
```

## 本领域的特殊提醒

**最大的风险不是设计错了，是"排期按软件节奏排"。**

典型事故链：

```
代码写完了 → 等打样 → 打样回来有错 → 改板 → 再等打样 → 发现 EMC 过不了 → 改拓扑 → 再打样
```

四轮下来两个月，而软件那边以为"功能早就完成了"。

**防御手段**：在 `04-实施路径.md` 里，硬件路径必须标出**关键路径**（打样、认证、长交期料），并明确"哪些软件工作可以在等待期并行做"。这一步不做，项目一定延期。
