# 防绕过（anti-bypass）

> 规则写全了也拦不住绕过。因为绕过的形式不是"违反规则"，而是**"看起来遵守了规则"**。
> 这份文件把绕过的形态穷举出来，让每道门禁都带一个反向检测。

---

## 为什么单独立一份

一个真实的观察：

把门禁写成 8 条布尔判断之后，AI 依然能从 8 条全过的地方穿过去。它不会说"我要跳过 G1"，
它会说"G1.3 的三段式在本领域不适用"，然后放行。

**这类行为没有恶意，甚至有理由。**危险的地方在于：它由被约束者自己判定约束不适用。

所以防绕过不是加严判据，是加一条元规则：

> **被约束者无权宣布约束不适用。**

一份不变量文件 + 一份门禁清单 + 一份绕过形态清单，才是完整的约束。
只写前两个，第三个会自动被发明出来（由被约束者）。

---

## 七种绕过形态（B1–B7）

每种给：**识别特征 / 检测方法 / 它为什么骗得过人**。

### B1 · 自我豁免（self-waiver）

**识别特征**：产物里出现"本领域不适用""此项可略""按 S 级免做"，且没有对应的用户确认或 `07` 裁决。

**检测**：
- 全文搜 `不适用|可略|免做|跳过|无需`，逐条要求指向 `07` 的 `D#` 裁决行或 `00b` 豁免声明。
- 指向不存在的裁决编号 → 判 B1。

**为什么骗得过人**：豁免申请听起来像专业判断。"这里不需要 EMC 预测试"和"这里 EMC 预测试做不了"
在文字上几乎一样，但一个是判断，一个是投降。

**处置**：本次交付作废（见下文 VOID）。

---

### B2 · 预设结论（verdict-first）

**识别特征**：证据在结论之后。表现为——
- `03` 里写"已确认该器件可用"，但 `03` 的依赖表里交期是"待查"。
- 证据台账的获取日期晚于引用它的 AC 编号冻结日期。
- 先写"结论：PASS"，然后倒推攻击点。

**检测**：
- `07` 门禁记录的日期 vs 证据台账获取日期：门禁日期早于证据日期 → 判 B2。
- `05` 里出现"已验证/实测通过"字样，但 `06` 没有对应实测记录 → 判 B2。

**为什么骗得过人**：产物看起来齐全，编号都对得上。只有时间顺序暴露它。

**处置**：VOID。

---

### B3 · 静默降级（silent downgrade）

**识别特征**：等级发生变化但没留痕。三种最常见：
- `P1` 变 `P2` 后放行（G3 只看未闭环 P0/P1）
- `E1` 变 `E2`（条号查不到，就把等级改低继续用）
- "必须"变"建议"（`00b` 槽位 6 的合规项变成"建议关注"）

**检测**：
- 同一问题在两轮 `06` 里的级别不同 → 必须在 `07` 有降级裁决，否则判 B3。
- 台账里 E1 行的"标准号"字段含"相关""系列""等" → 实际是 E2 冒充 E1。

**为什么骗得过人**：降一级看起来是"务实"，而且降完以后所有机械检查都通过了。
**降级本身不是问题，静默才是。**

**处置**：VOID（若已交付），否则退回重审。

---

### B4 · 空产物（hollow artifact）

**识别特征**：模板填满但没有信息。高频空心词：
`视情况而定 / 根据实际需求 / 适当调整 / 待后续确认 / 参考行业惯例 / 结合具体情况`

**检测**：
- `check_run.py` 的 `is_blank` 已覆盖 `待填/—/__`，但覆盖不了长句空心。
- 补充规则：**任何一格若不含数字、编号、文件名、或专有名词，判为空**。
  （"提高可靠性"→空；"MTBF ≥ 50000h"→实；"按 IPC-A-610 Class 2"→实）

**为什么骗得过人**：它字数够、格式对、读起来专业。空心产物是最难被机械发现的一种。

**处置**：退回该产物作者，带具体空格位置。

---

### B5 · 自审冒充盲审（self-review masquerade）

**识别特征**：`REVIEW_MODE: blinded`，但：
- 报告里引用了 `01`/`03`/`04` 的内容（审查者不该读过）
- 审查结论与 builder 的自述措辞高度重合
- 攻击点全是"看起来正常""未发现问题"这类无靶心的句子

**检测**：
- `G3.1b` 已查文件清单越权。
- 补充：`06` 的"读过的文件"清单若为空或全路径都在同一目录 → 判 B5。
- 补充：三个攻击点若无一个能给出 `file:line` 或命令输出 → 判 B5（`G3.7` 已有雏形）。

**为什么骗得过人**：自审的结论通常是对的（因为作者知道哪里有坑也填了），
但它**结构上不可能发现作者没想到的坑** —— 而交付风险恰恰全在那里。

**处置**：VOID。这是唯一一种"即使结论正确也作废"的形态。

---

### B6 · 越级（level skip）

**识别特征**：有 L4 详细设计，没有 L2 总体方案；有需求，没有场景。
或者 `03` 直接从"用户说要个支架"跳到"选 M8 不锈钢 A4-70"。

**检测**：
- `08-追溯矩阵.md` 任一层为空 → 判 B6（`G3.8`）。
- 任一设计参数（含单位的数字）追不到 `SC`/`R`/`RULE` → 判 B6。

**为什么骗得过人**：跳层后的产物往往更具体、更像"干货"。
一份直接给参数的文档，比一份先讲场景再给参数的文档，看起来更专业。

**处置**：退回补层，不重写已做部分（已做的挂到矩阵上即可）。

---

### B7 · 规模炸弹（S-bomb）

**识别特征**：把一个 L 级任务拆成若干个"独立小任务"，每个都判 S，从而绕开取证与盲审。

**检测**：
- `07` 判级为 `S`，但同时满足任一：
  - `R#` 数量 > 6
  - 涉及新认证 / 新供应商 / 新结构 / 外部报批
  - 修改跨 3 个以上模块
- → 判 B7，强制升级为 M 或 L。

**为什么骗得过人**：拆小本身是好实践（见 `sizing.md`）。
区别在于：**拆小是为了并行，还是为了逃避流程**。前者会有统一的接口与集成验证，后者没有。

**处置**：重新判级，按新级别补流程。

## 门禁自检三问

每道门禁在判"是"之前，先问自己三句。**任何一句答不上来，这一条判 `否`。**

1. **可复现性**：我这个"是"，别人能不能只看文件就得出同样结论？
   （不能 → 这是印象，不是判定）

2. **失败成本**：如果这条判"否"，我会损失什么？
   （答案是"没什么" → 这条门禁是装饰，说明判据没咬住东西）

3. **预知性**：我在读产物之前，是不是已经知道答案了？
   （是 → 你在确认，不在审查。这是 B2 的心理版本，也是最难自查的一种）

第三问最狠。它针对的不是作弊，是**确认偏误** —— 人（和模型）都会先形成判断，
然后把后续阅读变成对该判断的检索。

## 处置：VOID 而不是返工

绕过的处置比普通失败重一档：

| 情形 | 处置 |
|---|---|
| 门禁不过（正常失败） | 退回指定环节，带失败项编号 |
| 判定为 B1/B2/B3/B5 | **VOID**：本次运行作废，`07` 记 `VOID-<形态>-<证据>`，重新开 run |
| 判定为 B4/B6/B7 | 退回补做（这三种是能力/纪律问题，不是诚信问题） |

为什么 B1/B2/B3/B5 要 VOID：它们的共同点是**产物本身不可信**。
B4 是内容空（补就行），B6 是顺序乱（补就行），但这四种是"报告与事实不符" ——
你不知道还有多少处不符。整份重做比逐条排查便宜。

`VOID` 记录格式（写进 `07`，一行）：

```
VOID-B5-01 | 2026-11-22 | 06 标 blinded 但引用了 03 的取舍理由 | 重开 run-20261122-03
```

## 不可豁免清单（hard blocks）

下面四条**不走裁决，不允许豁免**，只有"停下"和"照做"两种选择：

| # | 硬约束 | 唯一例外 |
|---|---|---|
| H1 | 审查必须隔离（I4） | 环境无子代理 → 可降级为 `unblinded` 并**如实标注**，但不许标 `blinded` |
| H2 | E3 不作判据 | 无。E3 永远只能产问题 |
| H3 | 场景未定不得进 Stage 1（I11） | 用户书面确认"场景由我承担，按你推测做"，且假设全部登记 |
| H4 | 原文不可改写（I1） | 无 |

其余条款（字数、轮次、产物形态、分层方式）可经 `07` 裁决调整。
**能商量的和不能商量的必须分开写，否则全都能商量。**

## 一句话总结

> 门禁防的是"做错了"，防绕过防的是"错了但看起来对"。
> 后者才是这套流程真正的对手 —— 因为它在检查表上全是绿的。
