# 规则包（Rulepack）

> **作用**：把"符合行业规范"这个不可判定的句子，换成"符合 `RULE-FST-007`，出处 ASTM A320 §6.3"。
> **挂载点**：Stage 0 选包 → `03` 引用 → G2.9 校验 → `06` 按包攻击。
> **与领域包的区别**：领域包给方法论（怎么验证），规则包给判据库（合格线在哪）。

---

## 为什么需要规则包

这套流程禁掉了"符合国标""满足行业惯例"这类表述，因为它们不可判定。
但另一头的问题同样真实：**让 AI 从零推导所有设计规则既不可能也没必要。**

大部分规则是现成的、公开的、有编号的：
`GB/T 3098.1` 规定了螺栓的机械性能等级，`IPC-A-610` 规定了焊点的可接受外观，
`OWASP ASVS` 规定了认证模块的验证项。

规则包做的就是**把这些现成规则变成可引用的编号**，让：
- `03` 里每个量化参数都能挂到一个 `RULE-` 上（不再是"经验值"）
- `06` 的审查有靶心（按规则逐条打，而不是"我觉得这里有风险"）
- 用户能验收（规则可查，不是"专家说行"）

一句话：**规则包是"专业能力"的可审计形态。**

## 规则来源分级（R0–R3）

与 `domain-discovery.md` 的 E0–E3 是同一套思路，对象不同：E 级管"证据能不能用"，R 级管"规则能不能罚"。

| 级别 | 来源类型 | 例子 | 能否作拒收判据 |
|---|---|---|---|
| **R0** | 强制标准 / 法规 | GB 强制性国标、IEC 安全标准、ASTM 材料标准、行业准入法规 | **能** |
| **R1** | 行业规范 / 认证要求 | IPC-A-610、AEC-Q100、OWASP ASVS、CIS Benchmark | **能** |
| **R2** | 企业标准 / 客户规范 | 客户图纸技术要求、公司设计规范、供应商协议 | **能**（限本项目） |
| **R3** | 社区实践 / 公开 checklist | GitHub 上的 awesome-*、博客总结、开源项目约定、会议演讲建议 | **不能**，只能作建议（P1/P2） |

### R3 的硬边界（这条最容易被滥用）

R3 的价值很大 —— 它是**攻击面的来源**。一个成熟的 GitHub checklist 能告诉你
"这类项目通常会在哪 20 个地方翻车"，这比任何单条标准都有用。

但 R3 不能当判据，因为：
- 它没有责任主体（错了我找谁）
- 它没有适用范围界定（对 A 项目成立，对 B 不成立）
- 它经常是"某个团队的偏好"而非"行业的底线"

**允许的用法**：
```
✅ 按 R3 checklist 第 7 条，这里可能存在电偶腐蚀风险 → 转为攻击点，去 R0/R1 找判据
✅ 按 R3 建议，日志应含 trace id → 记为 P2 改进项
❌ 按 R3 checklist，此处不合格，拒收
```

**机械检查**：`rulepack` 里 `level: R3` 的规则，`severity_if_fail` 只能是 `advise`。
写成 `reject`/`block` → 规则包本身不合格，不得挂载。

## 规则包格式

一个规则包是一个目录：

```
rulepacks/hw-fastener-cold/
  rulepack.yaml      # 规则定义（唯一必需文件）
  sources.md         # 来源摘录（可选，但 R0/R1 必须能给出条号）
  README.md          # 适用范围与已知局限
```

### `rulepack.yaml` 骨架

```yaml
pack: hw-fastener-cold          # 唯一标识，小写连字符
version: 1.2.0                  # 语义化版本，锁定后不得漂移
domain: hardware
applies_to: ["低温", "凝露", "振动"]     # 四域标签，见 scenario.md §场景分类学
maintainer: 内部工艺科
last_reviewed: 2026-11-22

sources:
  - id: SRC-ASTM-A320
    title: ASTM A320/A320M Standard Specification for Alloy-Steel and Stainless Steel Bolting for Low-Temperature Service
    year: 2021
    level: R0
    how_to_verify: 标准全文库 / 供应商质保书引用
  - id: SRC-GBT-3098-1
    title: GB/T 3098.1-2010 紧固件机械性能 螺栓、螺钉和螺柱
    year: 2010
    level: R0

rules:
  - id: RULE-FST-001
    text: 服役温度低于材料脆性转变温度区间时，材料须在该温度下满足规定的冲击吸收能量
    source: SRC-ASTM-A320
    clause: "§6.3 与 Table 3（具体数值以标准正文为准）"
    level: R0
    severity_if_fail: reject
    check: 索取材料质保书中的低温冲击试验值，与标准要求比对
    evidence_needed: 材料质保书 + 第三方低温冲击报告
    drives: [DC1]
```

### 五个必填字段（缺一不可引用）

| 字段 | 作用 | 不合格示例 |
|---|---|---|
| `id` | 唯一、稳定、可引用 | `rule1`（无领域前缀，易撞） |
| `source` + `clause` | 出处可核 | `source: 国标`（哪本国标？） |
| `level` | R0–R3 | 空 |
| `severity_if_fail` | `reject` / `block` / `advise` | `high`（不是本体系的词） |
| `evidence_needed` | 怎么证明满足 | `符合要求`（等于没说） |

**`check` 字段强烈建议填**：它决定这条规则是"能验的"还是"只能说的"。
一条写不出 check 的规则，实质是口号。

### 用这份清单的三条纪律

1. **只能引用你核过条号的**。清单里有 `GB/T 1804`，不等于你知道它第几条规定了什么。
2. **版本要写年份**。`GB/T 1804` 不同年份的默认公差档不同。
3. **清单外的来源也能用**，但必须过同样的五字段要求 —— 不是"只有清单里的算数"。

## 规则裁剪（避免几百条全上）

一个完整规则包可能有几百条。全上会导致：`03` 字数爆炸（I6）、审查无法聚焦、用户看不懂。

裁剪靠 `applies_to` 与场景标签的交集：

```
场景标签: 低温×凝露×振动×食品接触
  → 命中: hw-fastener-cold（R0 低温螺栓、盐雾）
  → 命中: hw-food-contact（R0 材料迁移）
  → 不命中: hw-emc（无电子件）
  → 不命中: hw-atex（非防爆区）
```

裁剪后仍要保留**未命中清单**，写进 `03`。理由：某些规则的不适用本身需要判断，
把"为什么没挂这个包"写下来，比默默不挂安全。

## 规则冲突处理

| 冲突类型 | 处置 |
|---|---|
| R0 与 R0 冲突（两个强制标准要求不同） | 取**更严**者，并在 `03` 写明两个出处 |
| R0 与 R1/R2 冲突 | R0 优先；被覆盖方若必须满足，记 `07` 豁免及其代价 |
| R1 与 R2 冲突（客户要求低于行业） | R2 优先（项目内有效），但必须写明风险并让用户确认 |
| 同级冲突且无法取严 | 报 `07` 裁决，不许自行择一 |

**"取严"不是万能解法**：更严往往意味着更贵、更慢。取严时必须在 `03` 的取舍记录里写代价。

## G2.9 · 规则包门禁

`03-架构方案.md` 写完时判：

- [ ] `03` 有"规则包引用"段，列出挂载的 `pack@version`（版本号必须写，不许 `latest`）
- [ ] 每条 `DC` 与关键量化参数，挂 `RULE-` 或 `EV-`，无空来源
- [ ] 引用的 `RULE-` 在对应包里真实存在（防空引用）
- [ ] 没有 `R3` 规则被用作 pass/fail 判据
- [ ] 未挂载的候选包，写明不适用理由
- [ ] 规则冲突已按上表处置并留痕

**不过时怎么办**：退回 architect 补引用。
**不许把"经验值"当规则** —— 给不出 RULE 就给不出判据，这条参数就该进假设登记表（`00d` §5）。

## 这条设计在防什么

| 失败模式 | 没有规则包会怎样 | 有规则包会怎样 |
|---|---|---|
| 参数无出处 | "公差 0.1，经验值" → 出错无法归因 | 挂 `RULE-`，错也知道错在谁 |
| 假标准号 | "符合 GB/T 3098" 一路通过 | 必须给条号，编不出来就露 |
| 社区经验当硬标准 | 按某个博客的 checklist 拒收，供应商不认 | R3 只能 advise，机械可查 |
| 规则版本漂移 | 半年前查的规则，标准已改版 | 锁 `pack@version`，改版必须显式升级 |
| 审查无靶心 | "整体看没什么问题" | 按规则逐条打，漏打即无效审查 |

## 一句话

> 规则包不提高 AI 的专业水平，它提高的是**专业水平的可审计性**。
> 前者靠模型，后者靠这套东西 —— 而交付靠的是后者。
