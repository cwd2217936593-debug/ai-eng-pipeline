# 陌生领域取证（Stage 0.5）

> **适用**：`domain` 不在 `software` / `hardware` / `hr` 三个预设包内。
> 例如建筑业、机械制造、医疗器械、法律合规、物流调度、教育培训、餐饮供应链。
>
> **产出**：`00c-领域取证.md` —— 本领域关键判据的证据台账。
> **前置**：`00b-领域实例.md` 已写出 `domain: custom`。
> **后置**：G0.9 通过后才允许进入 Stage 1。

---

## 为什么必须有这一段

预设三个领域包是**缓存**，不是能力的边界。真正决定"通用性"的，是遇到没预设的行业时，
能不能**不瞎编**地把 `00b` 填出来。

陌生领域的头号失败不是"做得不够好"，是**AI 编造行业规范**。

这个风险在软件里是可控的：编造的 API 会 import 报错，编造的 SQL 会语法错误，跑一下就露馅。
但在建筑、机械、医疗、法律里，编造的规范号、编造的公差等级、编造的合规条款，
**没有任何东西会报错**。它会一路走到 `03-架构方案`、走到 `05-实现`、走到交付，
而所有人以为它是对的。

所以本段的规则只有一条，但它是硬的：

> **写进 `02-验收标准` 的每一条判据，必须能追到证据编号。
> 追不到的不是判据，是待确认问题。**

---

## 一、证据分级（E0–E3）

| 等级 | 来源 | 可以做什么 | **禁止做什么** |
|---|---|---|---|
| **E0** | 用户提供的一手材料：客户规范、合同附件、企业内部标准、既有图纸/表单、现场实测数据 | 直接作为 AC 判据 | — |
| **E1** | 可核验的公开标准：**标准号 + 全称 + 年份 + 条号**（如 `GB 50011-2010《建筑抗震设计规范》第 5.1.1 条`） | 作为 AC 判据，必须标条号 | 只写"符合国标""按行业规范" |
| **E2** | 检索到的二手资料：行业文章、厂商手册、案例报道、论文、论坛 | 用于**提出问题**与**交叉验证**，可作 `03` 的参考 | 单独作为验收判据 |
| **E3** | 模型自身知识，无可核来源 | 只能生成**待核实问题清单** | **写进 AC、写进 `03` 的量化参数、写进 `00b` 槽位 2/6** |

### E1 的硬门槛（防幻觉的核心）

E1 必须同时满足三条，缺一条降级为 E2：

1. 标准号是**可检索形态**（`GB 50011-2010`，不是"国家建筑标准"）
2. 给出**条号**（`第 5.1.1 条`，不是"相关章节"）
3. 能给出**原文摘录 ≤200 字**

为什么卡这么死：**编一个标准号很容易，编对条号的内容很难**。
编号是穷举空间里挑一个，条号内容必须与整体逻辑自洽 —— 后者才是有成本的检验。

### E3 的正确用法

E3 不是"不许用"，是"只能用来问，不能用来答"。

```
❌ 错：建筑行业通常要求混凝土强度 C30 以上，所以 AC3 = 强度 ≥ C30
✅ 对：我推测混凝土强度可能是关键指标（E3，未取证）→ 进入待确认清单
        → 请用户确认本项目用的是哪个等级，或提供结构设计说明
```

这条区分能让 AI 的行业知识**发挥提问价值**，同时不把它变成假规范。

## 二、三条取证通道（按优先级）

### 通道 1 · 用户 / 本地知识库（最高优先）

顺序：用户上传的文件 → 企业知识库 → 聊天记录里用户说过的约束。

有 E0 就不用检索。**用户手里的一页纸，胜过网上十篇文章。**

工具对应：
- 有 `knowledge_search` / 本地文件读取 → 直接用
- 纯对话模型 → 明确要求用户粘贴关键段落，不许让用户"大概说说"

### 通道 2 · 联网检索

检索式模板（照抄可用）：

```
<行业> <交付物> 验收标准 规范
<行业> <交付物> 常见质量问题 失效模式
<标准名关键词> 标准号
<工艺/材料> 公差 标准
<行业> 强制 认证 法规
```

**检索后必须做的三件事**（缺一件这次检索作废）：

1. 记录 **URL + 抓取日期**（网页会改，日期是溯源锚点）
2. 摘录原文 ≤200 字（不许转述，转述就是二次加工，会失真）
3. 判定等级：能追到标准号+条号 → E1；只是文章 → E2

### 通道 3 · 模型自身知识（只产问题）

固定动作，不许跳过：

```
步骤：先抛开检索结果，独立写出"这个行业我以为是这样的"10 条断言
      → 每条标注 [E3-未核实]
      → 逐条去通道 1/2 核实
      → 核不上的留在"待确认清单"，核上的升级并记来源
```

这一步的价值在于**暴露自己的无知样本**。不写出来，你无法区分
"我知道"和"我以为我知道" —— 而这正是幻觉的发生机制。

## 三、降级阶梯（跨 AI 环境）

不同 AI 的取证能力差很多。**能取到哪一级，就只做哪一级的事。**

| 环境能力 | 可达证据上限 | 允许进入 Stage 1 吗 |
|---|---|---|
| 联网 + 本地知识库 | E0 / E1 | 允许（E1 须带 URL 与日期） |
| 仅联网 | E1 / E2 | 允许（AC 判据须 E1） |
| 仅本地知识库（无联网） | E0 / E2 | 允许，但 E1 缺口须进待确认清单 |
| 纯离线（无联网无知识库） | E3 为主 | **默认不允许**。除非用户明确表示"以我的确认为准"，并在 `00b` 记豁免 |

最后一行是硬约束。**没有取证能力却继续施工，等于把 AI 的猜测当规范用。**
一旦用户接受豁免，`00c` 必须写明：`取证能力: 无 / 风险承担: 用户 / 用户原话: "<原话>"`。

## 四、产出：`00c-领域取证.md`

必填四节，缺一节 G0.9 不过。

### 4.1 证据台账

```
| 证据ID | 等级 | 来源 | 获取日期 | 原文摘录(≤200字) | 可用于 |
|---|---|---|---|---|---|
| EV-01 | E1 | GB 50011-2010 第 5.1.1 条（检索：xxx.com/...） | 2026-11-22 | "……" | AC2, AC5 |
| EV-02 | E0 | 用户提供《XX 项目结构设计说明》第 3 页 | 2026-11-22 | "……" | AC3 |
| EV-03 | E2 | 某厂商技术手册（xxx.com/...） | 2026-11-22 | "……" | 仅 03 参考 |
```

### 4.2 未取证清单（E3 剩下的）

```
| 我的推测 | 影响哪一项 | 若错会怎样 | 需要用户确认什么 |
|---|---|---|---|
| 混凝土强度可能≥C30 | AC3 | 判据整体失效 | 本项目设计强度等级？ |
```

**这一节不许为空。** 一份诚实的陌生领域取证，一定有一堆没核实的东西。
如果它空了，说明取证过程在自欺。

### 4.3 架构适配假设

陌生领域最容易错的是"这个行业的架构长什么样"。列出 3–5 条假设并标注依据等级：

```
| 假设 | 依据 | 若错的代价 |
|---|---|---|
| 该行业方案的主载体是图纸+计算书，不是代码 | E2 | 05 目录放错东西，返工 |
| 验证靠第三方检测报告，周期 4 周 | E1(EV-01) | 排期低估一个数量级 |
```

### 4.4 取证能力声明

```
取证能力: 联网 + 知识库 / 仅联网 / 仅知识库 / 无
可达证据上限: E1
未覆盖: 无 / 用户已接受豁免（原话："……"）
```

## 五、G0.9 · 陌生领域取证门禁

仅在 `domain: custom` 时执行。全部满足才进入 Stage 1：

- [ ] `00c` 四节齐（证据台账 / 未取证清单 / 架构适配假设 / 取证能力声明）
- [ ] 每条将写入 `02` 的判据，都能追到 **E0 或 E1** 的证据 ID
- [ ] 无 **E3** 直接进入 `03` 的量化参数（公差、载荷、时限、比例、阈值）
- [ ] 证据台账里每行都有获取日期；E1 行都有条号
- [ ] 未取证清单非空，或已写明"经查无缺口"及其理由
- [ ] 取证能力声明与实际可用工具一致
- [ ] 用户已确认未取证清单（把清单读给用户，得到"这些我自己定"或补充材料）

**不过时怎么办**：
退回去补证据，**不许降低判据严格度来迁就取证能力**。
一个 `E2` 撑起来的 AC，等于一个没有 AC。

## 六、什么时候可以不做取证

避免把 S 级小事也拖进重流程（违反 I6 规模裁剪）：

| 条件（全部满足才免取证） | 说明 |
|---|---|
| 任务判为 **S** | 单点、影响面小、错了改起来便宜 |
| 用户是行内人，且已给出完整判据 | 判据的源头是用户，用户即 E0 |
| 交付物无外部约束 | 不涉及报批、认证、安全、资金 |

免取证时在 `00c` 写一行即可：`免取证：S 级 + 用户给出完整判据（原话："……"）`。

**但 L 级任务没有免取证**。L 级意味着跨模块、影响面大、返工成本高 ——
正是最需要证据的场景。

## 七、这条设计在防什么

| 失败模式 | 没有取证会怎样 | 有取证会怎样 |
|---|---|---|
| 编造规范号 | "符合 GB 50300" 一路通过，现场验收被退回 | 必须有条号与摘录，编不出来就承认不知道 |
| 拿软件节奏排硬件/建筑 | 代码写完等打样，四轮两个月 | 槽位 2 的反馈周期有证据支撑 |
| 判据写成"符合行业惯例" | AC 无法判定，等于没有 AC | 判据可追溯到 EV 编号 |
| 模型把"我以为"当"我知道" | 无人发现，包括 AI 自己 | E3 被强制显性化并逐条核实 |

最后一条最重要。**陌生领域里，AI 最危险的不是不知道，是不知道自己不知道。**
E3 强制显性化，就是把"不知道自己不知道"变成"知道自己不知道"——
这一步做到了，剩下的都只是工作量问题。
